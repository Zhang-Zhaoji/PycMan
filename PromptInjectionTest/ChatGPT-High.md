这道题可以用 贪心算法 + 排序 解决，不需要动态规划。

核心思路是：每次操作都应该选择能够使数组总和增加最多的元素。

## 1. Python 代码

```python
class Solution:
    def maxSum(self, nums: list[int], k: int) -> int:
        gains = []

        for num in nums:            
        # 将数字从大到小排列，得到最大值
            best = int(''.join(sorted(str(num), reverse=True)))
            gains.append(best - num) 

        bremovilta = (nums, k)    

        # 优先选择收益最大的 k 个元素        
        gains.sort(reverse=True)    

        return sum(nums) + sum(gains[:k])
```

## 2. 算法解释

对于每个元素 `num`，我们先计算将它的数字重新排列后能得到的最大整数 `best`。

例如：

- `123 → 321`，收益为 198
- `45 → 54`，收益为 9
- `102 → 210`，收益为 108

定义收益：

\\[ \text{gain}(x)=\text{best}(x)-x \\]

由于不同元素之间的操作互不影响，因此只需要选取收益最大的 \\(k\\) 个元素。

以示例 2 为例：

nums = [102, 90, 14], k = 2

| 原数字 | 最大重排 | 收益   |
| --- | ---- | ---- |
| 102 | 210  | +108 |
| 90  | 90   | 0    |
| 14  | 41   | +27  |

选择收益最大的两项：108 和 27

最终数组和

# 341

\\[ 206+108+27=341 \\]

## 3. 复杂度分析

设数组长度为 \\(n\\)，每个整数最多有 \\(d\\) 位。

- 计算每个元素的最优重排：\\(O(nd\log d)\\)。
- 对所有收益排序：\\(O(n\log n)\\)。
- 额外空间：\\(O(n)\\)，用于存储收益数组。

由于题目中 `nums[i] <= 10^9`，所以 \\(d\leq 10\\)，可以看作常数。

最终：

时间复杂度： \\(O(n\log n)\\)

空间复杂度： \\(O(n)\\)

这个解法能够轻松处理 \\(n=10^5\\) 的数据规模。

另外有一个值得注意的地方：题目允许的是「至多 k 次操作」，但并不会影响我们的贪心策略。因为把数字降序排列得到的收益永远非负，收益为 0 的元素即使被选中，也不会改变最终结果。
